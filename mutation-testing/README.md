# Mutation testing (issue #128)

Line coverage tells us code *ran*; mutation testing tells us whether the tests
would *notice* if it were wrong. We inject small bugs ("mutants": `>` → `>=`,
`-` → `+`, `return Ok(())`, `true`/`false`, …) into security-critical code and
check that at least one test fails for each.

## Tool

[`cargo-mutants`](https://mutants.rs/) **27.1.0** (pinned in `run.py` and the
workflow).

- Works on stable Rust, needs no source instrumentation or nightly features.
- Understands `#[cfg(test)]` and never mutates test code.
- Supports file/regex scoping, diff-only runs (`--in-diff`) and sharding,
  which keeps CI bounded.
- Writes machine-readable results (`mutants.out/outcomes.json`).

## Scope

All scope lives in [`run.py`](run.py) (`SUITES`). Each suite pairs the code
under mutation with the tests that are expected to kill it.

| Suite | Mutated code | Tests run per mutant | Why |
|---|---|---|---|
| `contract-math` | `predifi-contract/src/payouts.rs`, `safe_math.rs` | lib tests matching `payouts::`, `safe_math::`, `payout_proptests` (incl. `mutation_kill_*`) | Fee deduction, payout pool, proportional winnings, referral cut, rounding direction; a bug here moves funds. |
| `contract-guards` | Guard functions in `predifi-contract/src/lib.rs`: `has_role`, `require_*` (admin / operator / oracle role checks, pause), `is_paused`, `is_valid_fee_bps`, `is_pool_active`, `is_valid_state_transition` | access-control audit, pause/unpause, `is_pool_active`, fee-bps, unauthorized / paused / canceled / resolved-pool tests | Authorization and pool-state gates in front of every privileged or state-changing entry point. |
| `access-control` | `access-control/src/lib.rs` (whole file) | all `access-control` lib tests | Role storage, assignment, revocation, transfer, and admin hand-over. |
| `backend-jwt` | `backend/src/jwt.rs` | backend lib tests matching `jwt::` | The backend's authorization boundary: signature, pinned HS256 (no `alg:none`), required `exp`, token type, key version, bearer parsing. The backend has no role model; JWT verification is the only auth decision. |

### Excluded, with rationale

| Excluded | Rationale |
|---|---|
| All `#[cfg(test)]` code, `*_tests.rs`, `test.rs`, `test_utils.rs` | Test code; mutating it is circular. cargo-mutants skips it automatically. |
| `predifi-contract/src/events.rs` | `#[contractevent]` structs: macro-generated (de)serialization with no logic. |
| `#[contracttype]` / `#[contracterror]` derives in all crates | Generated by soroban-sdk macros; cargo-mutants does not mutate macro output. |
| `safe_math.rs`: `PayoutRoundingAudit` | Test/audit helper with no on-chain caller (`grep` finds no use outside `safe_math.rs` tests). |
| Rest of `predifi-contract/src/lib.rs`, `pool.rs`, `prediction.rs`, `admin.rs`, `treasury.rs` | Orchestration (storage I/O, token transfers, events). Their payout, auth and state decisions delegate to the scoped functions above. Mutating them would require the full contract suite (~10 min per mutant, and it currently has pre-existing failing stress tests), which cannot stay bounded in CI. Candidates for a later, nightly-only extension. |
| `oracle.rs`, `price_feed*.rs`, `gas_opt.rs`, `referral.rs`, `challenge.rs` | Not payout/fee/role/pool-state logic; oracle math has its own proptests. |
| Rest of `backend/` (`routes/`, `db/`, `redis_cache.rs`, `jwt_security.rs` revocation) | Needs Postgres/Redis containers per mutant; token issuance in `jwt_security.rs` is covered indirectly because every issued token is verified by the mutated `jwt.rs`. |

## Running

```bash
cargo install cargo-mutants --locked --version 27.1.0

python3 mutation-testing/run.py --list                       # list mutants, run nothing
python3 mutation-testing/run.py                              # full baseline, all suites
python3 mutation-testing/run.py --suite access-control       # one suite
python3 mutation-testing/run.py --diff-base origin/main      # only lines changed vs main
python3 mutation-testing/run.py --report-only                # re-gate results in out/
```

Results are written to `mutation-testing/out/<suite>/mutants.out/`
(`caught.txt`, `missed.txt`, `outcomes.json`, per-mutant logs and diffs).

## The gate

A run passes only if every **missed** mutant (all tests still passed) is listed
in [`survivors.toml`](survivors.toml) with a reviewed disposition:

- `equivalent`: the mutant behaves identically for every input (explain why).
- `unreachable`: the mutated branch cannot execute in production (state the invariant).
- `accepted-risk`: reachable, but deliberately not tested (explain the risk and why it is acceptable).

Entries are keyed by `file: description` (no line numbers) plus
`line_contains`, a snippet of the original source line, so each entry pins one
mutation site and survives unrelated edits. Mutants of the same kind on the
same line share an entry; the rationale must cover that. Anything unlisted is
a test gap: add a test that kills it. Full runs also list entries that no
longer match anything, so they can be removed.
`Timeout` counts as detected. `Unviable` mutants (they don't compile, e.g.
`Default::default()` for a type without `Default`) are excluded from the score.

## CI

[`.github/workflows/mutation-testing.yml`](../.github/workflows/mutation-testing.yml)

- **Pull requests** touching scoped files run `--diff-base origin/<base>`, so
  only mutants on changed lines run. Typically a few minutes; 30-minute cap.
- **Push to `main`, weekly (Mon 03:00 UTC), manual dispatch** run the full
  baseline as a matrix of one job per suite shard, each capped at 30 minutes.
- Results are uploaded as workflow artifacts; the score table goes to the job
  summary.

What the initial run found, and how each was resolved:

| Missed mutant | Real bug it represents | Resolution |
|---|---|---|
| access-control `revoke_role` / `revoke_all_roles`: `count > 0` → `count >= 0` | Revoking an Operator while `OperatorCount` is already 0 (legacy / out-of-sync state) would underflow `u32` and panic. | Killed: `test_revoke_role_operator_count_saturates_at_zero`, `test_revoke_all_roles_operator_count_saturates_at_zero` |
| `calculate_claim_payout`: negative-stake check `\|\|` → `&&` (×2) | A negative stake paired with a zero stake would skip validation and return `Ok(0)`. | Killed: `mutation_kill_negative_*_with_zero_*_is_rejected` |
| `calculate_referral_amount`: zero-guard `\|\|` → `&&` (×2) | Zero pool, negative fee or negative user stake would error or misbehave instead of returning `Ok(0)`. | Killed: `mutation_kill_referral_each_guard_is_independent` |
| `calculate_odds_bps`: zero-guard `\|\|` → `&&` | A negative stake would produce a negative quotient cast to a huge `u64` odds value. | Killed: `mutation_kill_odds_negative_inputs_return_zero` |
| `SafeMath::proportion`: input-guard `\|\|` → `&&` | `proportion(0, 0, x)` would return `Ok(0)`; a negative `amount` would yield a negative payout. | Killed: `mutation_kill_proportion_input_guards_are_independent` |
| `PredifiContract::is_valid_state_transition` (`true` / `false`) | INV-2 helper had no test at all. | Killed: `mutation_kill_state_transition_table` |
| 5 redundant zero/fee short-circuits in `payouts.rs` / `safe_math.rs` | None: they behave identically. | Documented in `survivors.toml` as `equivalent`, with the reasoning. |

Two fixes to existing tests were needed to get a green baseline (cargo-mutants
refuses to run if the unmutated tests fail):

- `safe_math::tests::property_tests::safe_sub_rejects_underflow` could never
  generate an underflow (`a <= 0`, `b = a + deficit` gives `a - b = -deficit`),
  so proptest aborted with "too many rejects". It now draws `a` from
  `[i128::MIN, i128::MIN + b)`.
- `mutation_kill_safe_sub_underflow_is_error` asserted `safe_sub(0, 1)` is an
  error, but on `i128` that is `-1`. It now checks `i128::MIN - 1`.
